## D-2. AI 사용 범위

### 기계적으로 처리

같은 입력에 같은 결과가 필요하고 검증 가능한 값은 AI에 맡기지 않는다.

| 항목 | 처리 |
|---|---|
| baseline 선택, MD 계산 | DB/서버 규칙 |
| 주말·공휴일·PTO, availability, 동시 담당 | 서버 계산 |
| 기획 착수일·단계별 일정 | 역산 함수 |
| 위험도와 범위 축소/연기/TF 대안 | 조건식 + 동일 일정 엔진 |
| 수신자·발송시점·중복 방지 | 운영 규칙 |

**날짜, MD, 부족 영업일, TF 필요량은 AI가 생성하거나 수정하지 않는다.**

### AI에 맡길 부분

계산 완료된 JSON만 입력해 다음 표현 작업에 사용한다.

- 위험 원인 요약
- 리더/담당자별 문구 조정
- 기존 일정과 변경 일정의 차이 요약
- 여러 대안의 비교 설명

### 월 사용량·비용 가정

- 월 알림: **100건**
- 1건당 입력 **1,200 tokens**, 출력 **250 tokens**
- GPT-5 mini 단가 가정: 입력 **$0.25 / 1M**, 출력 **$2.00 / 1M**

`입력 120,000 tokens = $0.03`  
`출력 25,000 tokens = $0.05`

→ **월 약 $0.08**

비용을 절반으로 줄이면 정상/주의 알림은 템플릿으로 전환하고, `danger` 상태나 복수 대안 설명만 AI를 사용한다.  
AI 호출을 100건 → 50건으로 줄이면 약 **$0.04 / 월**이다.

## D-4. AI 사용 기록

AI에게 과제 전체 답을 한 번에 요청하기보다, 내가 사용할 데이터와 방향을 먼저 정한 뒤 **예외·부작용·구현 시 주의점**을 질문하는 방식으로 사용하였다.

### 사용 도구 / 질문 예시

- **ChatGPT:** 정의·계산 규칙 검토, SQL/Python/HTML 구현 보조, 문서 표현 정리
- **GitHub 저장소 연결:** docs / scripts / sql 간 정합성 확인
- **Python / SQLite:** AI 제안 수치와 SQL 결과 재계산

질문 예:
- `orig_estimate`를 Size 기준으로 쓸 때 `Category × Process`별로 나눌 필요가 있는지
- Worklog 결측을 `orig_estimate`로 보정해도 되는지
- 복수 Fix Version을 어떻게 처리해야 중복 집계를 막는지
- `resolved → dev started`를 검수 proxy로 쓸 때 제외할 조건은 무엇인지
- availability와 동시 담당을 함께 반영할 때 어떤 값을 가정으로 표시해야 하는지

### AI가 잘못 판단했고 수정한 지점

**1. B-1에서 샘플 데이터 부족을 문제로 해석함**  
AI는 Raw sample의 데이터가 충분하지 않다며 Pagination으로 추가 수집해야 한다고 제안했다. 그러나 해당 파일은 구조 확인용 샘플이므로, 데이터 수가 아니라 **현재 구조를 A의 MD 정의에 맞게 어떻게 가공할지**가 핵심이라고 판단했다. Pagination 내용은 제외하고 시간 표준화, Worklog 분리, role 연결, Fix Version, Custom Field Mapping에 집중했다.

**2. Size 계산 불가 시 기존 `size_label`을 다시 사용하려 함**  
초기에는 `COALESCE(size_class, size_label_raw)` 방식이 제안됐다. 하지만 A에서 기존 Size를 주관적 값으로 제외했으므로 다시 fallback하면 정의와 충돌한다. 따라서 `Category × Process × orig_estimate`로 계산할 수 없으면 `UNCLASSIFIED`로 두고, `size_label_raw`는 원본 보존용으로만 사용했다.

**3. B-2 필드 매핑이 실제 Schema와 달랐음**  
초기 답변에는 `issue.status_id`, `issue.status_name`, `change_event.*`처럼 실제 `schema.sql`에 없는 컬럼이 포함됐다. GitHub에서 매핑표와 DDL을 직접 대조해 `issue.status`, `issue.assignee_person_key`, `issue_status_history.*` 등 실제 Schema 기준으로 수정했다.

AI 답은 초안으로만 사용하고, 최종 수치·컬럼·정책은 제공 데이터와 실제 코드 실행 결과로 다시 확인하였다.
